# Claims and evidence

This reference connects each mathematical or software claim to its evidence and
limits. [STATUS](../STATUS.md) gives the short project overview;
[THEORY_MAP](THEORY_MAP.md) maps article statements to implementation.

“Proof in the article” identifies a written argument, not formal verification.
“Tested” identifies the checks listed in that row, not universal correctness.
“Open” marks an obligation that is not yet established. Test commands describe
how to repeat checks.

Some entries are not repository tests: the status column then says how the claim is checked (for
example by the script `docker/release/validate.sh`) or that no repository test checks it. The
software claims are about the three packages `cubeproof`, `neighbourly` and `faces12-campaign`; the
behavior they refer to is specified in the [SPECIFICATION](SPECIFICATION.md).

The column of each check names the target that runs it: `make test-fast` (the default
tier), `make test-architecture`, `make test-installed`, pytest `--run-slow` (more than about
ten seconds), or `make test-all` in the test image (the pinned CaDiCaL and cake_lpr).

Generated from `docs/claims.json` by `python3 tools/checks/claims_docs.py`, which
`make lint` runs with `--check`. Edit the registry rather than the table.
